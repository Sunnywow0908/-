# 6A 模块与团队其他角色端的集成边界

## 本次完成（范围限定）

- 公共基础：统一 SQLite、角色数据模型、API 响应/异常、初始化及演示数据
- 学生端：选修课程列表、个人周课表、已发布教学大纲查询
- 测试：公共模块、学生端正常场景、异常场景

## 留给其他成员的模块

- 教师端：教师授课课表、教学资源查看等，**尚未实现**
- 教研室主任端：教师开课情况、课程简介等，**尚未实现**
- 教学督导端：课程开设与教学资源使用情况等，**尚未实现**

这些内容仅说明团队后续对接方向，并非声明它们已经通过本 Sprint 验收。

## API 兼容约定

所有读接口遵循 `/api/v1/` 前缀、`code`/`message`/`data` JSON 响应字段、`BusinessError` 显式业务异常。
建议其他角色端创建独立路由文件，复用 `公共基础模块/db.py` 中 `get_db`，避免在每个功能中重复建立数据库连接。

## 用户故事验收建议

1. 给定学生 `S2024001`，在第 1 周能看到三项课表安排；在第 10 周新增 AI999；第 20 周只剩 MA101。
2. 给定学生 `S2024002`，无法查询 `CS101` 的大纲，也不能看见其他学生的课程。
3. 给定课程 `AI999`，列表中可见“未发布”，点击访问对应 API 时返回明确的 404 状态。
4. 角色为教师/主任/督导时，访问学生端接口返回 403。
5. 输入不合法教学周返回标准 422，数据库断开返回不泄漏细节的标准 503。

## 已知限制

这是虚构数据教学原型，尚无真实授权身份上下文、正式数据库迁移方案、跨服务集成测试、可观察性与性能测试。只有 6A 范围内的单元/接口集成测试，不得作为完整团队工程全部功能达标的证明。
